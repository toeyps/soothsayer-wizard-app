## A. ทำให้แกะโปรแกรมยาก

โค้ด Rust ถูกแปลงเป็นคำสั่งเครื่องใน `.exe` คนที่ได้ไฟล์ไปใช้เครื่องมือ reverse engineering แปลงกลับเป็นโค้ดคร่าว ๆ ได้ หมวดนี้ทำให้สิ่งที่ได้กลับมาอ่านยากขึ้น **ไม่ได้กันการโจมตี ไม่ได้เข้ารหัส** และคนที่เก่งและมีเวลายังแกะได้

การตั้งค่าอยู่ที่ `[profile.release]` ใน `src-tauri/Cargo.toml` และ `RUSTFLAGS` ใน `scripts/build-installer-windows.ps1` มีผลเฉพาะตอน build ตัวติดตั้ง ไม่มีผลกับ `tauri dev`

### `strip = true`: ตัดชื่อออก
- **ทำงานอย่างไร:** ลบตารางชื่อฟังก์ชันและข้อมูล debug ออกจากไฟล์ตอนท้าย
- **ช่วยอย่างไร:** ฟังก์ชันภายในเหลือเป็นแค่ตำแหน่งในหน่วยความจำ คนแกะต้องเดาเองว่าแต่ละตัวทำอะไร
- **ข้อจำกัด:** ข้อความที่โปรแกรมต้องใช้ตอนทำงานยังอยู่ เช่นชื่อคำสั่งที่หน้าจอเรียก (`compute_health_preview` ยังค้นเจอใน `tauri-app.exe` ของ 0.15.3) และชื่อฟิลด์ JSON

### `lto = true`: รวมโค้ดทั้งโปรแกรมก่อนปรับแต่ง
- **ทำงานอย่างไร:** ปกติ compiler ปรับแต่งโค้ดแยกเป็นส่วน ๆ ตัวนี้ดูพร้อมกันทั้งโปรแกรมรวมไลบรารี จึงฝังฟังก์ชันเข้าหากันและลบส่วนที่ไม่ใช้ได้
- **ช่วยอย่างไร:** ขอบเขตของแต่ละฟังก์ชันเลือนลง และโค้ดที่ไม่ได้ใช้หายไป เป็นผลพลอยได้ เป้าหมายหลักของมันคือให้โปรแกรมเล็กและเร็วขึ้น

### `codegen-units = 1`: compile เป็นก้อนเดียว
- **ทำงานอย่างไร:** ปกติ Rust แบ่งโค้ดเป็นหลายก้อนเพื่อ compile ขนานกัน ตัวนี้ให้เหลือก้อนเดียว
- **ช่วยอย่างไร:** compiler เห็นโค้ดครบจึงปรับแต่งได้มากขึ้น เสริมผลของ `lto` ด้านการแกะเป็นผลทางอ้อมเช่นกัน

### `--remap-path-prefix`: ซ่อน path ของเครื่อง
- **ทำงานอย่างไร:** ตอน compile จะมี path ของไฟล์ติดไปในโปรแกรม เช่นในข้อความ error ตัวนี้เปลี่ยน path ของ repo เป็น `wizard` และโฟลเดอร์ user เป็น `~`
- **ช่วยอย่างไร:** ไฟล์ที่ส่งให้ลูกค้าไม่เผยชื่อ user และโครงสร้างโฟลเดอร์ในเครื่องผู้พัฒนา
- **ผลที่ตรวจแล้ว:** ค้นใน `tauri-app.exe` ของ 0.15.3 ไม่เจอ `toey_` และ `C:\00_DATA`
- **สคริปต์ mac:** ใส่แล้ว แต่ยังไม่เคย build จริงบน mac

### ไม่ได้ใส่โดยตั้งใจ
- **`panic = "abort"`:** จะทำให้ panic ในคำสั่งเดียวปิดทั้งแอป จึงคง `unwind` ไว้
- **JS obfuscation:** ตัดสินใจข้าม โค้ดหน้าจอ minify แล้วและไม่มี source map แต่ยังแกะจาก exe ได้ และเห็นชื่อคำสั่ง

### เวลา build และขนาดไฟล์

วัดเมื่อ 2026-10-27 ด้วยโค้ดชุดเดียวกัน เริ่มจาก target ว่าง:

| | เวลา compile Rust | ขนาด exe |
|---|---|---|
| ไม่มีการตั้งค่าชุดนี้ | 3 นาที 10 วินาที | 16.9 MB |
| มีการตั้งค่าชุดนี้ | 4 นาที 56 วินาที | 15.9 MB |

ช้าขึ้นราว 1 นาที 45 วินาทีต่อรอบ เป็นตัวเลขรวมทั้งชุด ไม่ได้วัดแยกทีละตัว ตามหลักการ `lto` กับ `codegen-units = 1` น่าจะเป็นส่วนใหญ่ เพราะต้องวิเคราะห์ทั้งโปรแกรมและเสียการทำงานขนาน ส่วน `--remap-path-prefix` ทำให้ dependency ต้อง compile ใหม่หมดเมื่อค่าเปลี่ยน เช่นรอบแรกหลังเพิ่มหรือเมื่อย้ายเครื่อง

## B. ล็อก sidecar

Relation model คำนวณใน `backend-*.exe` ซึ่งอยู่ในโฟลเดอร์ติดตั้ง ก่อน 0.14.0 ใครก็เรียกตรง ๆ ได้โดยส่ง JSON เข้าไป

- **วิธีล็อก:** ทุกบรรทัดที่แอปส่งเป็น `<เวลา> <ลายเซ็น HMAC-SHA256> <JSON งาน>` sidecar ตรวจลายเซ็นก่อนทำงาน
- **sidecar ปฏิเสธเมื่อ:** ไม่มีลายเซ็น ลายเซ็นผิด ข้อมูลถูกแก้ หรือเวลาห่างเกิน 300 วินาที (กันเอาบรรทัดเก่ามาส่งซ้ำ)
- **ชื่อ algorithm:** ข้อความที่ส่งให้ sidecar ใช้ key `smoothing` แทนชื่อ algorithm และ `tauri-app.exe` ของ 0.15.3 ค้นไม่เจอ `LinearGAM`

**ข้อจำกัด**
- กุญแจลับฝังอยู่ในโปรแกรมทั้งสองฝั่ง (`SIDECAR_KEY` ใน `lib.rs`, `_KEY` ใน `backend.py`) และเก็บใน git คนที่แกะกุญแจออกมาได้จะเซ็นคำสั่งเองได้ ทางเลือกที่ยังไม่ทำคือให้สคริปต์ build อ่านกุญแจจากเครื่อง build
- ซ่อนชื่อ `pygam` / `LinearGAM` ใน sidecar ไม่ได้ เพราะเป็นชื่อโมดูลที่ Python ต้องใช้ การค้นในไฟล์ `.exe` ไม่เจอคำนี้ไม่ได้แปลว่าหายไป เพราะไฟล์แบบ onefile ถูกบีบอัดอยู่
- ทุกครั้งที่แก้ `backend.py` ต้อง build sidecar ใหม่

## C. จำกัดสิทธิ์ของหน้าจอ

หน้าจอของแอปคือหน้าเว็บ ถ้าถูกแทรกโค้ดได้ ความเสียหายจะเท่ากับสิทธิ์ที่หน้าเว็บมี หมวดนี้จึงให้สิทธิ์น้อยที่สุด

- **CSP (`tauri.conf.json`):** โหลดสคริปต์จากตัวแอปเท่านั้น และไม่มี `'unsafe-inline'` ใน `script-src`
- **`'unsafe-eval'` ต้องอยู่:** กราฟ Scatter และ Pair Plot ใช้ไม่ได้ถ้าเอาออก เคยเอาออกแล้วพังใน 0.4.0 ([`../../CLAUDE.md`](../../CLAUDE.md) มีรายละเอียด)
- **`style="..."` ใน HTML string ไม่มีผลในแอปที่ build แล้ว:** สีใน tooltip จึงต้องใช้ `tooltipColourClass` เราไม่ได้แก้ CSP เพื่อเรื่องนี้
- **ไฟล์:** หน้าจอเข้าถึงได้เฉพาะ `$APPDATA` การเขียนไปที่ผู้ใช้เลือกต้องผ่านคำสั่ง Rust เฉพาะงาน
- **Shell และ opener:** ถอดออกจากหน้าจอแล้ว (2026-10-28) การเปิด sidecar และเปิดโฟลเดอร์ทำจาก Rust มีเทสต์กันไม่ให้สิทธิ์กลับมา
- **Devtools:** ปิดในตัวติดตั้ง
- **HTML ใน tooltip:** ชื่อจากไฟล์ CSV ถูก escape ก่อนแสดง และกรองค่าสี
- **รอตัดสินใจ:** ลด `dialog:default` เหลือ open + message

ทุกหน้าต่างเรียกคำสั่ง Rust ได้ชุดเดียวกัน เพราะยังไม่ได้จำกัดคำสั่งต่อหน้าต่าง ความเสี่ยงนี้ลดลงเมื่อลบ `write_user_file` แล้ว

## D. ไฟล์ที่อ่านและเขียน

| เรื่อง | กติกา | อยู่ที่ |
|---|---|---|
| ไฟล์ CSV ข้อมูล | ไม่เกิน 2 GB ต่อไฟล์ | `MAX_CSV_BYTES` |
| ไฟล์ Tag names และ mapping | ไม่เกิน 10 MB | `MAX_SIDE_CSV_BYTES` |
| path ที่หน้าจอส่งมาให้อ่าน | ต้องผ่าน `validate_read_path` (ไม่ว่าง ไม่มี NUL ไม่มี `..`) | `lib.rs` |
| การเขียนไฟล์ที่ผู้ใช้เลือก | ต้องมีคำสั่ง Rust เฉพาะงาน `write_user_file` ถูกลบแล้วและห้ามสร้างตัวเขียนทั่วไปอีก | `workspace_export.rs` เป็นตัวอย่าง |
| ชื่อไฟล์ที่เขียน | ห้ามสร้างจากชื่อดิบ | `workspace_export.rs` เป็นตัวอย่าง |
| สูตร special sensor | จำกัดความยาวและความลึก | formula engine |
| Error log | ถึง 5 MB แล้วย้ายเป็น `.old.log` ข้อความต่อรายการตัดที่ 4 KB รายละเอียดที่ 32 KB | `frontend-errors.log` |

`validate_read_path` ไม่ได้จำกัดว่าอ่านโฟลเดอร์ไหนได้ เพราะผู้ใช้เลือก CSV จากที่ใดก็ได้

## E. ยังไม่ได้ทำ

เรียงตามลำดับที่ผู้ใช้กำหนดเมื่อ 2026-10-27

| งาน | ปัญหาวันนี้ | หมายเหตุ |
|---|---|---|
| **Code signing** | installer ไม่ได้ลงชื่อ Windows เตือน SmartScreen และไม่มีอะไรยืนยันว่าไฟล์มาจากเราจริง | มีค่าใช้จ่าย ต้องถามก่อน |
| **License** | ใครได้ตัวติดตั้งก็ลงได้ไม่จำกัดเครื่องและไม่หมดอายุ นี่คือช่องโหว่ใหญ่สุด | ทำเป็นงานสุดท้าย เครื่องลูกค้าต่อได้แค่ intranet จึงต้องเป็นแบบ offline |
| **ไฟล์โปรเจกต์ใน `%APPDATA%`** | เป็น JSON อ่านและแก้ได้ | ข้อเสนอคือรวมไปทำพร้อม license |

## ตัดสินใจแล้วว่าไม่ทำ

- **ลงลายเซ็นไฟล์ Export (2026-10-28):** รูปแบบไฟล์ตั้งใจให้ต่างจากที่ระบบปลายทางใช้จริง ไฟล์ต้องส่งกลับมาแปลงเป็น metadata ที่เจ้าของระบบอยู่ดี จุดแปลงนั้นคือด่านตรวจแล้ว

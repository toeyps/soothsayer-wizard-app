# Requirement

รายการ requirement จาก user ที่ยังรอทำ แยกจาก `docs/handover/` (ซึ่งบันทึกงานที่ทำไปแล้ว)

- บันทึกโดย session requirement: 1 เรื่อง = 1 หัวข้อ เก็บคำพูดเดิม สิ่งที่ผู้ใช้ตัดสิน คำถามค้าง และสถานะ
- ตอบเพิ่มเมื่อไร แก้ในหัวข้อเดิม

## 2026-10-20 — หน้าต่าง Build Model ต้องมีปุ่มย่อ / ขยาย เหมือนแอปอื่น (session requirement)
- **ผู้ขอ:** user (ผู้ใช้เล่าใน session requirement)
- **คำพูดเดิม:** "หน้า build model มีแต่ปุ่มปิด ไม่มีปุ่มเก็บหน้าจอ หรือปุ่ม ย่อ ขยายหน้าจอเหมือน app อื่น"
- **ตีความ:** หน้าต่าง Build Model ต้องมีปุ่มควบคุมหน้าต่างครบ 3 ปุ่มแบบแอป Windows ทั่วไป: ย่อเก็บลง taskbar (minimize), ขยายเต็มจอ / คืนขนาด (maximize/restore), ปิด
- **สิ่งที่พบในโค้ด (ยังไม่แก้):** `Dashboard.tsx` สร้างหน้าต่าง `build-model` ด้วย `decorations: isMac` (บน Windows ไม่มีกรอบของระบบ) และ `maximized: true` · title bar ของหน้าต่างนี้เป็นของแอปเองและมีแต่ปุ่มปิด · หน้าต่างหลักใช้ `TitleBar.tsx` ซึ่งมี minimize / toggleMaximize อยู่แล้ว ใช้เป็นแบบอย่างได้ · หน้าต่าง Add Special Sensor (`decorations: false`) น่าจะเจอปัญหาเดียวกัน ต้องเช็คว่าจะทำด้วยหรือไม่
- **คำถามค้าง:** ไม่มีแล้ว — ผู้ใช้ตอบ (2026-11-02): **ได้** คือต้องลากย้ายหน้าต่างจากแถบหัวได้ และดับเบิลคลิกแถบหัวเพื่อขยาย/คืนขนาดได้ด้วย
- **ผู้ใช้ตัดสิน (2026-10-20):** หน้าต่าง Add Special Sensor **คงไว้แบบเดิม** (มีแต่ปุ่มปิด) — requirement นี้ทำเฉพาะหน้าต่าง Build Model
- **ขนาดโดยประมาณ:** Small–Medium (UI + อาจต้องเช็ค capability ของหน้าต่าง `build-model` ว่าอนุญาต `window:allow-minimize` / `allow-toggle-maximize`)
- **สถานะ:** ยังไม่เริ่ม (Not started) · บันทึกอย่างเดียว ไม่ได้แตะโค้ด

## 2026-11-02 — จำกัดจำนวน sensor tag ตาม license รวมทุก project (session requirement)
- **ผู้ขอ:** ผู้ใช้เล่าใน session requirement
- **คำพูดเดิม:** "ต้อง lock จำนวน sensor tag ตาม license ซึ่งผมยังไม่ได้ออกแบบ license method นะ ยกตัวอย่างว่า license นี้มีจำนวน tag sensor รวมทุก project ได้แค่ 1000 tag จะสร้างกี่ machine ก็ได้ ตราบใดที่จำนวน sensor รวมกันทุก project ไม่เกิน 1000"
- **ตีความ:** license กำหนดเพดานจำนวน sensor tag รวมของทุก project (1000 เป็นตัวอย่าง ไม่ใช่ค่าตายตัว) · จำนวน project / machine ไม่จำกัด ขอแค่ยอดรวม tag ไม่เกินเพดาน
- **ยังไม่ได้ออกแบบ:** วิธีทำ license ทั้งหมด (ผู้ใช้ระบุเองว่ายังไม่ได้ออกแบบ)
- **สิ่งที่พบในโค้ด:** ยังไม่มีระบบ license ใน `src/` และ `src-tauri/src/` · แต่ละ project เก็บเป็นไฟล์แยกใน `$APPDATA` ซึ่งเป็นไฟล์ที่ผู้ใช้แก้หรือลบเองได้ (ข้อนี้มีผลตอนออกแบบ เพราะยอดรวมต้องนับจากทุก project)
- **ผู้ใช้ตอบคำถาม (2026-11-02):**
  - **sensor ชื่อซ้ำข้าม machine นับแยก:** sensor a อยู่ใน machine A และ B = 2 tag — เหตุผล: "user อาจจะหลอกโดยการตั้งชื่อเหมือนกันและแต่ data หรือรายละเอียดต่างๆไม่เหมือนกันก็ได้" (ห้ามใช้ชื่อ tag ตัดซ้ำ)
  - **special sensor ไม่นับ:** นับแค่จาก master data ที่ import เข้าโปรแกรม
  - **นับจาก master data ทั้งหมด** ไม่ใช่เฉพาะที่เลือกใช้ — "import เข้าไปในโปรแกรมแล้วเท่ากับว่าคุณจะใช้สิ"
  - **เกินเพดานต้องแจ้งเตือนพร้อมตัวเลข:** ตัวอย่าง limit 1000 ใช้ไป 980 แล้ว upload master data 50 tag ต้องบอกเลยว่าเหลือโควตาแค่ 20 tag
  - **ลบ project ได้โควตาคืน:** ผู้ใช้ยอมรับเพราะการลบแปลว่าทิ้งงานวิเคราะห์ / FG / model ที่ train มาทั้งหมด
  - **license:** ยังไม่ได้ออกแบบ แต่คิดเร็วๆ ต้องผูกกับเครื่อง
- **ผู้ใช้ตอบรอบ 2 (2026-11-02):** โควตาไม่พอ = **ห้าม import เลย** "จนกว่าไฟล์ raw data และ master data จะเหลือ 20 หรือไม่เกิน" · โปรแกรม import data ใหม่เข้า project เดิมไม่ได้ และไม่มีปุ่ม Duplicate project (ผู้ใช้ท้วงว่าผมถามโดยไม่ได้ดูโค้ด — ถูกต้อง)
- **ตรวจโค้ดแล้ว (2026-11-02):**
  - ไฟล์ raw data / master data ตั้งครั้งเดียวตอนสร้าง project (`DataUploadPage.tsx:334,339`) ไม่มีที่อื่นเขียนทับ · `duplicateWorkspace` ถูกลบแล้ว 2026-10-28 (`ba9a922`) · ทางเดียวที่สร้าง project คือ New project
  - **master data ในแอปคือ "Tag-name file" ขั้นตอนที่ 2 และเป็นไฟล์ไม่บังคับ** (`isReady` ไม่ต้องใช้ไฟล์นี้, `DataUploadPage.tsx:280`) · sensor ที่ใช้งานได้จริงมาจากหัวคอลัมน์ของ raw data (`report.headers`) ไม่ใช่จาก master data · คอลัมน์ที่ไม่มีใน master data ยังใช้ได้ (แค่ไม่มีชื่อ) และแถวใน master data ที่ไม่มีใน raw data ไม่ถูกใช้ (`apply_mapping`)
  - เปิด project เดิมจะอ่านไฟล์ raw / master จาก path เดิมบนเครื่องใหม่ทุกครั้ง (`DataUploadPage.tsx:400,520`) → ถ้าไฟล์ถูกแก้ข้างนอกแอปให้มีคอลัมน์เพิ่ม จำนวน sensor เพิ่มได้โดยไม่ผ่านด่านตอน import
- **เคยตัดสินไปแล้ว (handover 2026-10-27/28 — ผมพลาดที่ไม่ได้อ่านก่อนถาม):** เครื่องลูกค้าต่อได้แค่ intranet → license ต้องเป็นแบบ **offline** · license เป็น **งานสุดท้าย** ของลำดับงานป้องกันโปรแกรม · ไอเดียเดิม "จำกัดจำนวน project ต่อลูกค้า" ถูกแทนด้วย requirement นี้ (machine ไม่จำกัด จำกัดที่จำนวน tag)
- **ผู้ใช้ตอบรอบ 3 (2026-11-03):** คำถาม (ก) ปิด — "master data กับ raw data ต้องมี tag เท่ากันผมถึงให้ import ได้ เท่ากับว่ามันจะไม่เกิด case ที่คุณบอก" · ตรงกับงานของ session dev วันที่ 2026-11-02 (entry "Import: บังคับใส่ master data และ sensor ต้องตรงกับ raw data") ซึ่งบังคับกฎนี้กับโปรเจกต์ใหม่แล้ว (ยังไม่ได้ลองในแอปจริง, ยังไม่ push) · ผมแก้ความเข้าใจในหัวข้อ "ตรวจโค้ดแล้ว" ด้านบนที่ว่า master data ไม่บังคับ: ข้อนั้นเลิกจริงแล้วสำหรับโปรเจกต์ใหม่
- **ผู้ใช้ตอบรอบ 4 (2026-11-03):** คำถาม (ข) ปิด เลือก "ก" = **เปิด project เดิมแล้วยอดรวมเกินโควตา ไม่ให้เปิด** จนกว่าจะลดไฟล์ลง · ตัวอย่างที่คุยกัน: limit 1000, Machine A 100 + Machine B 880, แก้ไฟล์ของ A ใน Excel เป็น 150 → รวม 1030 → เปิด A ไม่ได้ ต้องลดเหลือไม่เกิน 120 (1000 − 880) แล้วเปิดได้ตามเดิม งานไม่หาย · ถ้าเพิ่มแล้วยังไม่เกิน (A เป็น 110, รวม 990) เปิดได้ปกติและนับตามจริง · **กระทบงาน dev:** ตอนนี้การเปิดโปรเจกต์เดิมไม่ถูกเช็คเลย (entry "Import: บังคับใส่ master data…") ตอนทำ license ต้องเพิ่มการตรวจโควตาในขั้นเปิด project
- **คำถามค้าง:** ไม่มี · ที่ยังไม่ได้ออกแบบคือวิธีทำ license เอง (offline, ผูกเครื่อง, ทำเป็นงานสุดท้าย)
- **สถานะ:** ยังไม่เริ่ม (Not started) · บันทึกอย่างเดียว ไม่ได้แตะโค้ด

## 2026-11-05 — user อัปโหลดผล Export ขึ้น server ของลูกค้าได้เอง (session requirement)

- **ผู้ขอ:** ผู้ใช้เล่าใน session requirement
- **คำพูดเดิม:** "ตอนนี้ที่เราสามารถ export file model and data ออกมาได้ ซึ่งอนาตคจำเป็นต้องupload ไปยัง server ของลูกค้าได้เลย เพื่อให้สามารถใช้งานจริงได้ทันที โดยไม่ต้องผ่านทางทีมงานของเราแต่เป็น user สามารถทำได้เลย"
- **ตีความ:** เป็นงานอนาคต · user ส่งผล Export ขึ้น server ของลูกค้าได้เอง และ model ใช้งานจริงได้ทันที โดยทีมเราไม่ต้องอยู่ในขั้นตอน
- **ตรวจโค้ดและ handover แล้ว:**
  - Export results เขียนลงโฟลเดอร์ในเครื่องเท่านั้น (`export_workspace_results`, `lib.rs:6940`) · แอปไม่มีตัวส่งข้อมูลออกเครือข่าย และ CSP `connect-src` ใน `tauri.conf.json` อนุญาตแค่ตัวแอปเอง จึงต้องขออนุมัติเปิดสิทธิ์นี้ตอนทำ (ห้ามขยาย CSP โดยไม่ได้รับอนุมัติ)
  - **ขัดกับการตัดสินใจ 2026-10-28 ("Security #7"):** ไฟล์ Export จงใจไม่ใช่ format ที่ระบบปลายทางใช้จริง ต้องส่งกลับมาให้ผู้ใช้แปลงเป็น metadata และจุดนั้นคือด่านตรวจ จึงตัดสินใจไม่ลงลายเซ็นไฟล์ Export · ถ้าไม่ผ่านทีมเรา ด่านนี้หายไป ต้องกลับมาทบทวนเรื่องลายเซ็น
  - `WIZARD_OUTPUT_SPEC.md` ระบุว่าไฟล์ Export มีแค่ค่าที่ user เลือกและข้อมูล training แล้วไป train ใหม่ที่ปลายทาง จึงต้องมีตัวรับที่แปลงและ train ได้
  - เครื่องลูกค้าต่อได้แค่ intranet (2026-10-27) ใช้ได้ก็ต่อเมื่อ server อยู่ในเครือข่ายเดียวกัน ยังไม่ยืนยัน
- **ผู้ใช้ตอบ (2026-11-05):** (1) ขั้นแปลงไฟล์ยังไม่ตัดสิน: "เขียวไว้ทั้งก และ ข เลย เพราะเรื่องนี้ผมยังไม่ได้คุยกับทีมงานว่าจะแปลง format กันยังไง" = เก็บไว้ทั้งสองทาง: ก. โปรแกรมของเราบน server ลูกค้าตรวจ แปลง และ train · ข. Wizard แปลงให้เสร็จก่อนส่ง ("เขียว" ผมอ่านว่า "เขียน") · (2) server "มักจะอยู่ในเครือข่ายเดียวกัน เพราะว่าส่วนมากแล้วถ้าติดตั้ง on prem ที่ลูกค้า ก็จะเป็น intranet ของ user"
- **คำถามค้าง:** (ก) วิธีแปลง format รอผู้ใช้คุยกับทีม · (ข) server รับไฟล์ด้วยวิธีใด และมีช่องทางรับอยู่แล้วหรือยัง (ยังไม่ได้คำตอบ) · ลูกค้าที่ server ไม่อยู่ใน intranet เดียวกันจะทำอย่างไร ("มักจะ" แปลว่าอาจมีกรณีนี้)
- **สถานะ:** ยังไม่เริ่ม (Not started) · บันทึกอย่างเดียว ไม่ได้แตะโค้ด

## 2026-11-05 — ใช้ AI ช่วยสร้าง Failure Group (session requirement)
- **ผู้ขอ:** ทีมงาน (ผู้ใช้เล่าใน session requirement)
- **คำพูดเดิม:** "เพิ่ม requirement อันนี้เป็นทางทีมงานอยากให้ สามารถเพิ่ม ai or agentic ai or something เพื่อใช้ในการสร้าง failure group ได้"
- **ตีความ:** เพิ่ม AI เข้ามาช่วยสร้าง Failure Group · ยังไม่ระบุชนิดของ AI ("ai or agentic ai or something")
- **สิ่งที่พบ:**
  - ตอนนี้ผู้ใช้สร้าง Failure Group เองในแท็บ Failure Groups (`FailureGroupsPanel.tsx`) · ข้อมูลของกลุ่มคือชื่อ, คำอธิบาย และคำแนะนำ (`FailureGroup` ใน `types.ts`) และผูกกับ sensor ผ่าน model · ไม่พบการเรียกใช้ AI ในแอปและไม่พบการพูดถึงใน handover / backlog
  - เครื่องลูกค้าต่อได้แค่ intranet (2026-10-27) จึงเรียก AI บน cloud จากเครื่องลูกค้าโดยตรงไม่ได้ · แอปยังส่งข้อมูลออกเครือข่ายไม่ได้ (CSP `connect-src`)
- **คำถามค้าง:** (ก) AI ต้องทำอะไรบ้าง และใช้ข้อมูลอะไรเป็นตัวตั้ง · (ข) AI จะทำงานที่ไหน: บนเครื่อง user, บน server ใน intranet ของลูกค้า หรือบน cloud และข้อมูลของลูกค้าออกไปนอกองค์กรได้ไหม
- **สถานะ:** ยังไม่เริ่ม (Not started) · บันทึกอย่างเดียว ไม่ได้แตะโค้ด

## 🆕 2026-11-02 — Import: อ่านคอลัมน์แรกเป็นเวลา เมื่อไม่มีคอลัมน์ชื่อ timestamp / time (session dev)

- **ผู้ใช้สั่ง:** "แก้เรื่อง Date เลย ให้อ่านคอลัมน์แรกเป็นเวลา" (ผมเสนอทางนี้ เพราะป้ายบนหน้าจอเขียนว่า "First column is date/time" อยู่แล้ว)
- **เดิม:** หาคอลัมน์เวลาจากชื่อ `timestamp` / `time` เท่านั้น ไฟล์ที่ชื่อ `Date` ได้ 0 แถว และ `Date` กลายเป็น sensor
- **ใหม่:** แก้จุดเดียวใน `read_csv_with_stats`: ถ้าไม่มีคอลัมน์ชื่อนั้น คอลัมน์แรกคือเวลาและถูกเปลี่ยนชื่อเป็น `timestamp` ตั้งแต่ตอนอ่าน โค้ดส่วนอื่นที่ดูจากชื่อ (merge, report, รายชื่อ sensor, การเช็คกับ Tag names) จึงไม่ต้องแก้ · คอลัมน์ชื่อ `timestamp` / `time` ยังชนะเสมอ อยู่คอลัมน์ไหนก็ได้
- **แจ้งผู้ใช้:** กล่องเหลือง "<file>: column 'Date' was read as the date/time column (no column is named timestamp or time)."
- **ความเสี่ยงที่เหลือ:** ไฟล์ที่ไม่มีคอลัมน์เวลาจริง ๆ คอลัมน์แรกที่เป็นตัวเลขจะถูกอ่านเป็นเวลา ค่าอาจถูกตีความเป็นวันที่ (เช่น Excel serial) และไม่ใช่ sensor อีกต่อไป มีแค่กล่องเหลืองเตือน · โปรเจกต์เก่าที่ใช้ไฟล์แบบนี้ เปิดใหม่จะได้ข้อมูลจริงแทน 0 แถว
- **เทสต์:** โหลดไฟล์จริงผ่าน `read_merge_csvs_with_report` (Date, DateTime, ชื่อไทย, ชื่อว่าง, คอลัมน์ `time` ชนะ, หลายไฟล์ชื่อต่างกัน, เทียบกับ Tag names, คอลัมน์แรกไม่ใช่วันที่) · `cargo test --lib` ผ่าน 785 ข้อ
- **แผนทดสอบ:** IMP-65 → IMP-128, WFF-1 → WFF-18, เพิ่มไฟล์ `BRK-date-header-tags.csv` กลับมา
- **ยังไม่ได้ลองในแอปจริง** · commit ในเครื่อง ยังไม่ push

### Additions since the draft
1. **Every rule uses the displayed name** (description, or the tag when there is none); tag-only sensors join rules 2 and 3 like any other. Fit is measured in the rendered font (mono for tags).
2. **Tooltips, the user's #1 complaint. Real-app root cause:** `.tt-tag { flex-shrink: 0 }` in `App.css`, next to `.tt-desc { min-width: 0; overflow: hidden }` inside `.tt-label`, squeezes the description to width 0 and runs the tag under `.tt-val` (mock Today, GC12 · com, 4 Crosshead sensors: box 378 px, description width 0, tag right 1068 > value left 935; markup from `sensorInlineHtml`). 3. **Axis titles (v15, the user's last item).** A title that fits prints as today. Otherwise a rotated Y title wraps to at most 2 lines at word boundaries (a " - " break first, line 2 never starts with a separator, the unit stays with the last word; a name with no spaces breaks after `_ . -`). It may use its whole free column beyond the plot. If 2 lines cannot hold it, line 1 keeps the start and line 2 reads "… end · unit" in whole words; full name in `title`. The plot gives up one line (14 px) only when a tag line prints as well. Rule 3b applies on chart titles with a loose compare (ignoring spaces, punctuation, case: "SegmentNo 1" = "Segment No 1"): no tag line when the tag only re-spells the description, and the unit joins the title at title size (11.5 px, `--text-secondary`). A tag that truly differs keeps its line. A Scatter title that stays on one line and keeps its tag line stays description, then tag + unit. Applies to Scatter, Compare, Clusters (Model fit + Health score), Fit when the target has no unit. Line chart has no Y title; time charts print only the unit; pair plot keeps rule 5.
4. **Chart picker row:** stops 8 px before its icon buttons, pickers shrink (Today it runs 47 px under them). This fixes a Today bug, so at the user's width (1352 px) the picker row changes on short-name projects too. It is the one short-name change at that width besides the draft's list.

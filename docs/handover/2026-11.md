## 🆕 2026-11-02 — 📋 REQUIREMENT: จำกัดจำนวน sensor tag ตาม license รวมทุก project (session requirement)
- **ผู้ขอ:** ผู้ใช้เล่าใน session requirement
- **คำพูดเดิม:** "ต้อง lock จำนวน sensor tag ตาม license ซึ่งผมยังไม่ได้ออกแบบ license method นะ ยกตัวอย่างว่า license นี้มีจำนวน tag sensor รวมทุก project ได้แค่ 1000 tag จะสร้างกี่ machine ก็ได้ ตราบใดที่จำนวน sensor รวมกันทุก project ไม่เกิน 1000"
- **ตีความ:** license กำหนดเพดานจำนวน sensor tag รวมของทุก project (1000 เป็นตัวอย่าง ไม่ใช่ค่าตายตัว) · จำนวน project / machine ไม่จำกัด ขอแค่ยอดรวม tag ไม่เกินเพดาน
- **ยังไม่ได้ออกแบบ:** วิธีทำ license ทั้งหมด (ผู้ใช้ระบุเองว่ายังไม่ได้ออกแบบ)
- **สิ่งที่พบในโค้ด:** ยังไม่มีระบบ license ใน `src/` และ `src-tauri/src/` · แต่ละ project เก็บเป็นไฟล์แยกใน `$APPDATA` ซึ่งเป็นไฟล์ที่ผู้ใช้แก้หรือลบเองได้ (ข้อนี้มีผลตอนออกแบบ เพราะยอดรวมต้องนับจากทุก project)
- **ผู้ใช้ตอบคำถาม (2026-11-02):**
  - **sensor ชื่อซ้ำข้าม machine นับแยก:** sensor a อยู่ใน machine A และ B = 2 tag — เหตุผล: "user อาจจะหลอกโดยการตั้งชื่อเหมือนกันและแต่ data หรือรายละเอียดต่างๆไม่เหมือนกันก็ได้" (ห้ามใช้ชื่อ tag ตัดซ้ำ)
  - **special sensor ไม่นับ:** นับแค่จาก master data ที่ import เข้าโปรแกรม
  - **นับจาก master data ทั้งหมด** ไม่ใช่เฉพาะที่เลือกใช้ — "import เข้าไปในโปรแกรมแล้วเท่ากับว่าคุณจะใช้สิ"
  - **เกินเพดานต้องแจ้งเตือนพร้อมตัวเลข:** ตัวอย่าง limit 1000 ใช้ไป 980 แล้ว upload master data 50 tag ต้องบอกเลยว่าเหลือโควตาแค่ 20 tag
  - **ลบ project ได้โควตาคืน:** ผู้ใช้ยอมรับเพราะการลบแปลว่าทิ้งงานวิเคราะห์ / FG / model ที่ train มาทั้งหมด
  - **license:** ยังไม่ได้ออกแบบ แต่คิดเร็วๆ ต้องผูกกับเครื่อง
- **คำถามค้าง:** หลังแจ้งเตือนว่าโควตาไม่พอ จะให้ทำอะไรต่อ (ห้าม import เลย / เลือก import ได้แค่เท่าที่เหลือ) · แก้ master data เดิมใน project แล้วจำนวน tag เปลี่ยน นับใหม่อย่างไร · Duplicate project นับโควตาเพิ่มไหม · รายละเอียดวิธีทำ license (ยังไม่ออกแบบ)

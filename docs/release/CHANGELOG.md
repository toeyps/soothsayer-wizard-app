## [0.12.0] — 2026-10-21

Minor release — **Export results**: ส่งผลโมเดลทั้ง workspace ออกเป็นไฟล์ชุดเดียวสำหรับระบบ health score พร้อมข้อมูลเครื่อง (Plant · Machine) ที่ต้องกรอกเพื่อใช้ในการ export
workspace เก่าเปิดได้ตามเดิม (ไม่มีอะไรพัง) แต่มีพฤติกรรมบางอย่างเปลี่ยน ดูหัวข้อ "สิ่งที่เปลี่ยนจากเดิม" ด้านล่าง

### ✨ Features

- **ปุ่ม Export results ที่แถบล่างของหน้าต่าง Build Model** — กดได้เมื่อโมเดลทุกตัวเป็น Complete
  - หน้าต่าง Export แสดง checklist (ข้อมูลเครื่อง, time zone, running status, special sensor, โมเดล) ว่าอะไรครบ/ยังขาด พร้อมตัวอย่างโครงสร้างไฟล์และดูตัวอย่างเนื้อไฟล์ (Peek)
  - เลือกโฟลเดอร์ปลายทางเอง แอปสร้างโฟลเดอร์ใหม่ให้ทุกครั้ง (ชื่อเป็นภาษาอังกฤษ + วันที่เวลา) ไม่เขียนทับของเดิม
  - ไฟล์ที่ได้ตามสเปกกลางของ Wizard: `machine_info.json` และ `models/<ชื่อ>.json` + `.csv` ต่อโมเดล — ไม่มีไฟล์ `.pkl` ไม่มีข้อมูลดิบทั้งชุด ไม่มีชื่ออัลกอริทึม
  - ถ้ามี sensor ที่ไม่ได้ระบุ component แอปถามยืนยันก่อน export
  - ระหว่าง export ช่องตั้งค่าถูกล็อก มีสถานะ writing / done / failed, ยกเลิกได้, และเปิดโฟลเดอร์ผลลัพธ์ได้จากหน้าต่าง
- **ข้อมูลเครื่อง (Plant · Machine)** — กรอก Plant, Machine, Machine tag (บังคับ) และ Notes ตอนสร้าง project ชื่อ project คือ "Plant · Machine" (คู่นี้ห้ามซ้ำกับ project อื่น)
  - เมนู **Project details** เปิดได้จากปุ่ม Rename บน Recent card, เมนูชื่อ project บน title bar และเมนูแอป — บันทึกครั้งเดียวทั้งชื่อ, รายละเอียด, machine และ time zone
  - Step 2 แสดงบรรทัด time zone ของข้อมูล (ค่าเริ่มต้นตามเครื่อง เปลี่ยนได้) ใช้ประทับเวลาในไฟล์ที่ export
  - project เก่า: Plant ใช้ชื่อเดิม Machine/tag ว่างไว้ให้กรอก — แสดงชื่อเดิมจนกว่าจะกรอกครบ; Duplicate project ต่อท้ายชื่อ machine ด้วย " (Copy)" และคงสถานะ Complete ของโมเดล
- **Running status** — ระบุเงื่อนไขว่าเครื่องกำลังทำงานเมื่อ sensor ใดสูงกว่าค่าเท่าไร (ใช้เงื่อนไข "above" ตัวเดียวที่มีอยู่ หรือกำหนดที่บรรทัดใหม่ใน running condition) ส่งออกไปใน `machine_info.json`
- **ชื่อโมเดลห้ามซ้ำทั้ง project** — แอปตรวจตอนบันทึกและตอน Mark complete พร้อมบอกเหตุผล; โมเดลใหม่ได้ชื่อเริ่มต้นที่ไม่ซ้ำกันเอง (ต่อท้าย "(Relation model)" / "(Clustering)" / "(Individual)" เมื่อชน)
- โมเดลที่ไม่มี Category ถูกกันไม่ให้ Mark complete พร้อมบอกเหตุผล (เดิมบังคับเฉพาะก่อน Train)
- ตรวจสเปกก่อน export: input = output, X = Y, ชื่อ Failure Group ซ้ำ, ปัญหารายโมเดล — แสดงเป็นรายการปัญหาพร้อมชื่อ sensor (description ก่อน tag)

### ⚠️ สิ่งที่เปลี่ยนจากเดิม (workspace เก่าเปิดได้ แต่ผลอาจต่างจากเดิม)

- **Mark complete ไม่เขียนไฟล์อีกแล้ว** — เหลือแค่ตรวจและตั้งสถานะ Complete (ปุ่มแสดง "Checking…") ไฟล์ผลลัพธ์เขียนตอน Export results เท่านั้น; ลบข้อความ "Mark complete again" ที่เคยเตือนเมื่อไฟล์เก่ากว่าการตั้งค่า, และการลบโมเดล/Failure Group ไม่ต้องลบไฟล์ใน AppData อีก
- **แก้ set point ของโมเดลที่ Complete แล้ว → กลับเป็น Incomplete ทันที** ต้อง Mark complete ใหม่ (เดิมแก้ได้โดยสถานะคงเดิม)
- **ขอบเขตช่วง cluster ของ Clustering เปลี่ยนเป็น `min < ค่า <= max`** ค่าที่ตรงเส้นแบ่งพอดีจะอยู่ในช่วงล่าง (เดิมอยู่ช่วงบน) และใช้กติกาเดียวกันทั้ง Train, health score และ export
- **ขอบนอกของ cluster เปิด** — ค่า criteria ที่อยู่นอกช่วงที่ตั้งไว้จะได้คะแนนตาม cluster ริมสุด (เดิมไม่มีคะแนน); ถ้าช่วงซ้อนกัน แถวในส่วนซ้อนจะถูกใช้ train กับ cluster แรกเท่านั้น (เดิม train ทั้งสอง)
- ข้อความเตือน scoring periods เปลี่ยนจาก "…to save the new results" เป็น "…to confirm the new results"

### 🐛 Bug fixes

- Dashboard autosave ไม่เขียนทับชื่อ/รายละเอียด/ข้อมูลเครื่อง/time zone ที่เพิ่งบันทึกจากหน้าต่างอื่น
- Rename project มีทางบันทึกทางเดียว (Project details) — ไม่มีทางที่ชื่อสองที่ไม่ตรงกันอีก
- ถ้าแก้ set point ระหว่างที่แอปกำลังตรวจ Mark complete โมเดลจะคงเป็น Incomplete (ไม่ถูกตั้งเป็น Complete ด้วยค่าที่ยังไม่ได้ตรวจ)
- การตรวจ export ล้มเหลวทั้งชุดเพราะมีโมเดลเดียวตั้งค่าไม่ครบ ไม่ขึ้น "Export failed" ที่ไม่มีคำอธิบายอีก — แสดงเป็นปัญหารายโมเดลพร้อมปุ่ม Try again
- ชื่อไฟล์ที่ตรงกับชื่อ device ของ Windows (เช่น `NUL`) ถูกแปลงให้ปลอดภัยตอน export

### 🧪 Tests

- เพิ่มชุดทดสอบ contract ระหว่างหน้าจอกับ Rust ของ export, ทดสอบ export จริงแล้วตรวจไฟล์ตามสเปก, ทดสอบ import วันเวลาหลายรูปแบบและ follow-Y chart; อัปเดต manual test plan (827 รายการ)

### 🗑️ Removed

- การเขียนไฟล์ผลโมเดลตอน Mark complete (โฟลเดอร์ output ใน AppData, ไฟล์ `.pkl` และ `REL_DATASET.csv`) — แทนที่ด้วย Export results
- ปุ่มแก้ชื่อ project แบบ inline (ใช้ Project details แทน)

### 📝 Docs

- เพิ่มสเปกไฟล์ผลลัพธ์ของ Wizard (`docs/specs/WIZARD_OUTPUT_SPEC.md`) และลบเอกสารเก่าที่ไม่ได้ใช้แล้ว

## [0.11.1] — 2026-10-19

Patch release — ต่อจาก 0.11.0: **นำเข้า CSV ที่วันเวลาเขียนได้หลากหลายรูปแบบมากขึ้น** และ **เลิกเตือนเรื่อง sensor ซ้ำข้ามไฟล์**

### 🐛 Bug fixes

- **ไฟล์ข้อมูลจาก historian (เช่น `01-Jan-25 12:00 AM`) โหลดแล้วได้วันที่ถูกต้อง** — ใน 0.11.0 ไฟล์ลักษณะนี้ยังอ่านวันเวลาผิด
  สาเหตุหนึ่งคือมีอักขระซ่อน (UTF-8 BOM) นำหน้าชื่อคอลัมน์แรก ตอนนี้แอปตัดทิ้งให้ทุกหัวคอลัมน์ (ทั้งไฟล์ข้อมูลและไฟล์ mapping/metadata)
- **เลิกแสดงคำเตือน "Duplicate column … found in file 1, file 2"** สำหรับ sensor ที่มีในหลายไฟล์ —
  การเพิ่มหลายไฟล์คือข้อมูลชุดเดียวกันคนละช่วงเวลา ซึ่งเป็นเรื่องปกติ (คอลัมน์ที่ซ้ำกันภายในไฟล์เดียวยังถูกแจ้งเตือนเหมือนเดิม)

### ✨ Features

- **อ่านวันเวลาได้ครอบคลุมขึ้นมาก** นอกจากแบบ Excel ใน 0.11.0 แล้ว ตอนนี้รองรับ:
  - ชื่อเดือนภาษาอังกฤษ (ย่อ/เต็ม) และภาษาไทย ในทุกลำดับ เช่น `01-Jan-25`, `Jan 31, 2025`, `31 มกราคม 2568`
  - ปี 2 หลัก (อ่านเป็น 20YY; ปีไทย 2 หลักอ่านเป็น พ.ศ. 25YY) และเลขไทย
  - ชื่อวันนำหน้า และเขตเวลาท้าย (`Z`, `UTC`, `GMT+0700`, `+07:00`) — ใช้เวลาตามที่เขียนไว้
  - AM/PM ทุกแบบ รวมถึงคำว่า `น.` / `เวลา` / `พ.ศ.`
  - ตัวเลขติดกัน เช่น `20250131130500`, รูปแบบ ISO ที่ไม่มีเครื่องหมายคั่น (`T130500`) และทศนิยมแบบจุลภาค
  - คอลัมน์เวลาที่เป็นตัวเลขล้วน: วันที่แบบ Excel serial และ Unix epoch (วินาที/มิลลิวินาที, UTC)
  - แอปบอกในกล่องเตือนสีเหลืองของหน้า Import ว่าอ่านวันเวลาของแต่ละไฟล์เป็นรูปแบบไหน และแจ้งจำนวนแถวที่อ่านวันเวลาไม่ได้
  - หน้า Import แสดงตัวอย่างรูปแบบที่รองรับเพิ่มเติม

## [0.11.0] — 2026-10-19

Minor release (ฟีเจอร์ใหม่ + **พฤติกรรมการลบ Failure Group เปลี่ยน**) — ต่อจาก 0.10.1:
**ไฟล์โมเดลใน output ตรงกับสถานะจริงของโมเดลเสมอ** และ **นำเข้า CSV ที่วันเวลาเป็นแบบ Excel ได้**

### ⚠️ พฤติกรรมที่เปลี่ยน (โปรดอ่าน)

- **การลบ Failure Group จะลบโมเดลที่อยู่เฉพาะกลุ่มนั้นด้วย** — เดิมโมเดลเหล่านั้นถูกย้ายไปอยู่ "Not in group"
  ตอนนี้แอปจะถามยืนยันก่อน พร้อมบอกจำนวนโมเดลที่จะถูกลบ เมื่อยืนยันแล้ว **โมเดลและไฟล์ผลลัพธ์ของมันจะถูกลบจริง**
  - โมเดลที่อยู่ในกลุ่มอื่นด้วย จะไม่ถูกลบ แค่หลุดออกจากกลุ่มที่ลบ
  - ใช้กับปุ่มลบกลุ่มทั้งสองที่ (หน้ารายการกลุ่ม และในแผง Failure Groups)

### ✨ Features

- **นำเข้า CSV ที่วันเวลาเป็นแบบ Excel ได้** — เดิมไฟล์ที่เขียนวันที่แบบ `1/2/2026 23:55` จะอ่านวันเวลาผิดหมด
  ตอนนี้แอปอ่านได้ทั้ง เดือน/วัน/ปี, วัน/เดือน/ปี (คั่นด้วย `/` `.` หรือ `-`), ปี/เดือน/วัน, เวลาแบบ AM/PM และ ISO ที่ลงท้ายด้วย `Z`
  - **ลำดับวัน/เดือนตัดสินเป็นรายไฟล์:** ถ้ามีเลขเกิน 12 แสดงว่าเป็นวัน (เช่น `13/2/2026` คือวัน/เดือน) ถ้าทุกค่าไม่เกิน 12 แอปเลือกแบบที่เวลาเรียงต่อเนื่องกว่า
  - **แอปบอกว่าอ่านเป็นลำดับไหน** ในกล่องเตือนสีเหลืองของหน้า Import (เช่น "1/2/2026 → 2026-01-02") ถ้าเดาไม่ได้จริง ๆ จะเตือนให้ตรวจวันที่
  - ไฟล์หลายไฟล์ที่เขียนวันเวลาคนละรูปแบบ ก็รวมกันตามเวลาได้ตรงกัน
  - หน้า Import แสดงรายการรูปแบบที่อ่านได้ครบ 8 แบบ และบอกว่าปีต้องเป็น 4 หลัก

### 🐛 Bug fixes

- **Mark complete ใหม่ไม่ทำให้ไฟล์โมเดลเก่าสะสมในโฟลเดอร์ output** — ไฟล์ชุดเก่าของโมเดลเดียวกัน (เช่น Relation model ที่เปลี่ยน predictor,
  Clustering ที่เปลี่ยน Y sensor) จะถูกแทนที่ด้วยชุดใหม่ ไม่เหลือไฟล์ที่ไม่ตรงกับโมเดลปัจจุบัน และโมเดลอื่นไม่ถูกแตะ
- **ลบโมเดลแล้ว ไฟล์ผลลัพธ์ของโมเดลนั้นถูกลบด้วย** — เดิมไฟล์ค้างอยู่ในโฟลเดอร์ output ตลอดไป
  (ถ้าไฟล์ถูกเปิดค้างอยู่ เช่นใน Excel แอปจะแจ้งว่าลบไฟล์ไหนไม่ได้)
- โมเดลที่หายเพราะเอาออกจากกลุ่มสุดท้าย (มีปุ่ม Undo 7 วินาที) จะลบไฟล์เมื่อหมดเวลา Undo เท่านั้น

### ℹ️ ที่ไม่เปลี่ยน

- โมเดลที่กลับเป็น Incomplete (เช่น เปลี่ยนช่วงเวลา/predictor) **ยังเก็บไฟล์เดิมไว้** จนกว่าจะ Mark complete ใหม่
- ข้อมูล raw จากการ import ไม่ถูกปัดทศนิยม (เก็บค่าเต็มเหมือนเดิม)
- ไฟล์ค้างจากเวอร์ชันก่อนหน้าในเครื่องจะหายเมื่อ Mark complete โมเดลนั้นใหม่

### 🧪 Tests

- เพิ่มเทสต์การอ่านวันเวลาทุกรูปแบบ (รวมกฎเดาลำดับวัน/เดือน และเทสต์ที่เช็กว่ารายการรูปแบบบนหน้า Import ตรงกับที่ parser อ่านได้จริง),
  การแทนที่/ลบไฟล์โมเดลฝั่ง Rust, และการลบโมเดล/กลุ่มฝั่งหน้าจอ

## [0.10.1] — 2026-10-16

Patch release (ปรับปรุงเล็ก ๆ + แก้การแสดงผล ไม่มี breaking change) — ต่อจาก 0.10.0:
**กราฟตามเวลาใน Build Model ปรับแกน Y ตามช่วงที่ซูม**, **แถบ KPI หน้า Model fit เต็มความกว้าง** และ
**หน้า Import บอกชัด ๆ ว่าทุกไฟล์ต้องเขียน date/time รูปแบบเดียวกัน**

### 🐛 Bug fixes

- **กราฟตามเวลาในหน้า Model fit และ Health score ดูยากเมื่อซูม** — เดิมแกน Y ถูกตรึงตามข้อมูลทั้งช่วง ซูมเข้าไปแล้วเส้นยังแบนอยู่ในช่วงเดิม
  ตอนนี้แกน Y ปรับตามค่าที่เห็นในช่วงที่ซูม (เหมือนกราฟ Dashboard) โดย **ยังรวมเส้นของโมเดลไว้เสมอ**
  (±1SD / ±3SD, ขอบ L/H, ±2RMSE, เส้น 80 และ 0) เส้นเหล่านั้นจึงไม่หลุดออกนอกกราฟ และขีดบนแกนยังห่างเท่ากัน
  - กราฟคะแนนใน Health score ยังคงแสดง 0–100 ตามเดิม และกราฟ Clustering ไม่เปลี่ยน
- **แถบ KPI ของหน้า Model fit ไม่เต็มความกว้าง** — ทั้ง 3 tile ขยายเต็มพื้นที่เหมือนแถบของหน้า Health score

### ✨ Improvements

- **หน้า Import: เมื่อเพิ่มไฟล์ CSV ตั้งแต่ 2 ไฟล์ขึ้นไป จะมีกล่องแจ้งว่าทุกไฟล์ต้องเขียน date/time รูปแบบเดียวกัน**
  (การรวมไฟล์จับคู่จากข้อความของ timestamp) พร้อมตัวอย่างที่ถูก/ผิด และรายการรูปแบบที่แอปอ่านได้ 5 แบบ

  และอาการที่สั้นกว่า 1 ชั่วโมงจะถูกเฉลี่ยจนเบาลง
  - ชั่วโมงที่เครื่องไม่เดิน (ไม่ผ่าน Running condition) ไม่ถูกนำมาเฉลี่ยและ **ไม่มีคะแนน**

  - ไฟล์โมเดลที่ Mark complete เขียนออกมาจะบอกว่าคะแนนคิดจากค่าเฉลี่ย 1 ชั่วโมง

  workspace เก่าเปิดได้และโมเดล Complete ยังเป็น Complete (ค่าเดิมเหล่านั้นจะหายไปเมื่อแก้ช่วงนั้นจริง)
- **Clustering ใช้ได้ไม่เกิน 5 cluster** และโมเดล Clustering ใหม่เริ่มที่ 1 cluster (โมเดลเก่าที่เกิน 5 เปิดได้ ลดจำนวนได้อย่างเดียว)
- **สูตร special sensor เก่าแบบ Excel `round($A, 2)` ถูกแปลงอัตโนมัติตอนเปิด workspace** เป็น `round($A * 100) / 100`
  แล้วแจ้งผู้ใช้ — ค่าที่ได้จะต่างจากที่เคยแสดง เพราะสูตรแบบเดิมคำนวณผิดมาตลอด
- **สูตรที่ใช้ชื่อหรือฟังก์ชันที่ไม่มีอยู่จริง (พิมพ์ผิด) ถูกปฏิเสธพร้อมบอกวิธีแก้** แทนที่จะสร้าง sensor ว่างแล้วขึ้น "Updated"

### ✨ Features

- **Failure groups เป็นขั้นที่ 3 ของหน้า Import** — สร้างกลุ่มก่อนเข้า Dashboard; Dashboard เปิดที่แท็บ Failure Groups พร้อมสรุปและโหมด assign sensor;
  การ์ดโปรเจกต์ล่าสุดบนหน้าแรกมีชิปบอกจำนวน Failure group
- **ชื่อ sensor ขึ้นด้วย description ก่อน แล้วตามด้วย tag ทุกที่** และมีตัวเลือก sensor / ตัวเลือกสีแบบเดียวกันทั้งแอป
  (ค้นหาได้ทั้ง description / tag / หน่วย / component, เลือกหลายตัวแล้วกด OK) — ไม่แสดงรหัสสี hex
  - ค่าที่ผู้ใช้พิมพ์เองแสดงตามที่พิมพ์ (เช่น เงื่อนไข `> 0.0005` ไม่ถูกปัดเป็น 0.001); ค่าที่คำนวณไม่แสดงเป็น 0 ถ้าไม่ใช่ 0 จริง
  - เงื่อนไข Filter ของ sensor ที่ถูกเอาออกจากกราฟยังมีผล พร้อมป้ายเตือนและปุ่ม "Show on chart / Remove"
- **ตัวแก้สูตร special sensor ใหม่** — เติมคำอัตโนมัติ, ขีดเส้นใต้ส่วนที่ผิดพร้อมคำอธิบาย, ดูตัวอย่างผลจริงบนกราฟก่อนบันทึก,
  **Quick build** สร้างสูตรจาก sensor ที่เลือก (รวม Average / Sum / Median / ปัดทศนิยม), เพิ่มฟังก์ชัน `ln`,

  - special sensor ที่เปิด workspace แล้วกู้คืนไม่ได้ ซ่อมได้โดยแก้สูตร ("No data — fix formula"); โมเดลที่ train บน sensor นั้นกลับเป็น Incomplete
  - แก้สูตรของ sensor ที่โมเดลใช้อยู่ ทำให้โมเดลขึ้น "Settings changed" ต้อง Train ใหม่ก่อน Mark complete
- **Train sensor / Train all แบบคิว** ใน Build Model — Train ทีละตัว มีหน้าตรวจก่อนเริ่ม (พร้อมลิงก์ Fix →), แถบความคืบหน้า + เวลาที่เหลือ,
  Cancel หยุดหลังตัวปัจจุบัน, ตั้งค่าของโมเดลที่อยู่ในคิวถูกล็อก และเตือนก่อนปิดหน้าต่างระหว่าง train; เมนู Train บอกสถานะรายตัว
  และเหตุผลที่ train ไม่ได้เป็นชื่อสิ่งที่ขาด
- **หน้าตั้ง Running condition ใหม่** — มี timeline ของช่วง Train / Scoring, แถวช่วงเวลาบรรทัดเดียว (พร้อมจำนวนวันที่เดิน),
  ช่วงที่ผิดบล็อก Apply พร้อมบอกว่าแก้ช่วงไหน, **บรรทัดบอกผลกระทบก่อนกด Apply** (กี่โมเดลจะกลับเป็น Incomplete) และบรรทัดแจ้งหลัง Apply

- **Build Model Workbench จัดหน้าใหม่**
  - หน้า Model fit: แถบ KPI tile (Mean · SD · Outside ±3SD / R² · RMSE · Residual SD / Clusters · In a cluster · Inside 3× SD) แทนตารางสถิติ,

- **1 โมเดลอยู่ได้หลาย Failure Group พร้อมกัน และ 1 sensor มีได้หลายชนิดโมเดลพร้อมกัน** — เดิมโมเดลผูกกับกลุ่มเดียวแบบตายตัว ถ้าอยากให้โผล่ในอีกกลุ่มต้องสร้างสำเนาแยกที่แก้แล้วไม่ตามกัน ตอนนี้เป็นความสัมพันธ์แบบ many-to-many จริง และ sensor ตัวเดียวถือ Individual + Relationship + Clustering พร้อมกันได้
- **การสร้าง/ลบโมเดลย้ายมาอยู่ที่ Dashboard ทั้งหมด** — ติ๊กปุ่ม I / R / C ที่ sensor ในแผงขวาได้เลย ปุ่มเดียวทำทั้งเพิ่มและเอาออก ไม่ต้องเปิดหน้าต่าง Build Model ก่อน (หน้าต่าง Build Model เหลือหน้าที่แก้ไข/เทรนโมเดลที่มีอยู่แล้วอย่างเดียว)
- **"Not in Group" ใช้งานได้จริงแล้ว** — กองสำหรับโมเดลที่ยังไม่ผูกกับ failure mode ไหน ตอนนี้มองเห็น เพิ่มโมเดลเข้าไปได้ และเอาออกได้จริง (เดิมมีอยู่ในโครงสร้างข้อมูลแต่ใช้งานไม่ได้)
- **"Colour by value" ของกราฟ Scatter กลับมาแล้ว** — ย้ายไปอยู่ในแท็บ Highlights ระบายสีจุดตามค่าของ sensor ที่เลือก
- **แก้ชื่อ/คำอธิบาย/คำแนะนำของ Failure Group ได้จาก Dashboard โดยตรง** — ไม่ต้องเปิดหน้าต่าง Build Model เหมือนเดิม
- **Highlight แถวกลุ่มที่ sensor เป็นสมาชิกอยู่** ในเมนูเพิ่มเข้า Failure Group — พอมีกลุ่มเยอะ (10+) จะเห็นทันทีว่าตัวไหนติ๊กอยู่ ไม่ต้องไล่หา
- **Auto-fill Target sensor** ตอนเพิ่มโมเดล ถ้ากลุ่มนั้นมี sensor ที่เข้าเงื่อนไขอยู่ตัวเดียว
- **กันงานหายตอนปิดแอป** — ถ้าปิดโปรแกรมภายในเสี้ยววินาทีหลังแก้อะไรบางอย่าง ตอนนี้แอปจะรอเซฟให้เสร็จก่อนปิดจริง (เดิมการแก้ครั้งสุดท้ายอาจหายไปเงียบๆ)

- **เพิ่มแท็บ "Highlights"** — ตีกรอบช่วงเวลาที่สนใจ (ตั้งชื่อ+เลือกสี) แสดงเป็นแถบไฮไลต์บนกราฟ Line (โหมด band หรือ "Line-colour" ให้เส้นเปลี่ยนสีตามช่วง) และเป็นวงแหวนไฮไลต์จุดบน Scatter (Pair Plot ไม่รองรับ ใช้ lasso-cluster ของตัวเองแทน)
- **เพิ่มฟีเจอร์ Tag Point** — เทียบค่าจุดข้อมูล 2 จุดขึ้นไปแบบ side-by-side บนกราฟ Line และ Scatter กดไอคอน 🏷️ ในกล่องเครื่องมือแล้วคลิกจุดที่สนใจ ได้ badge เลข + การ์ดลอยโชว์ค่าทุก sensor ที่จุดนั้น คลิกจุดเดิมซ้ำเพื่อลบ tag ออก (ตั้งใจไม่ persist ลง workspace file — ปิดแอปแล้วเปิดใหม่ tag หายตามต้องการของผู้ใช้)

## [0.2.1] — 2026-08-11

เวอร์ชันก่อนหน้าที่เคย build เป็น installer จริงคือ **0.1.6** — เวอร์ชันนี้จึงรวมงานสะสมทั้งหมดตั้งแต่นั้นมา (0.2.1 เคยถูกตั้งไว้ในโค้ดมาสักพักแต่ไม่เคย build/แจกจริงมาก่อน) รวมทั้งหมด 10 commit

### ⚠️ Breaking change

- **ลบ operation "Product", "Subtract", "Divide" ออกจากเครื่องมือคำนวณ special sensor** — ตัดออกทั้งจาก calculation engine, หน้าจอ Add Special Sensor, และ chart-display pipeline ฝั่ง Rust เหตุผล: subtract/divide ต้องเลือก "base sensor" ซึ่งใช้งานสับสนและมักถูกใช้ผิด ส่วน product ไม่มี use case เหลือแล้วหลังตัดสองตัวนั้นออก **workspace เก่าที่เคยสร้าง special sensor ด้วย 3 operation นี้จะคำนวณค่าไม่ได้อีกต่อไป** — เหลือแค่ Sum / Average / Median สำหรับรวมหลาย sensor

### ✨ ฟีเจอร์ใหม่ / ปรับปรุงใหญ่

- **ออกแบบหน้าจอ "Add Special Sensor" ใหม่ทั้งหมด** — จากเดิมที่ต้องเลือกโหมด Simple/Advanced + Single/Multi Calc ก่อนถึงจะเห็น operation จริง เปลี่ยนเป็นพาเนลเดียวที่ปรับตัวเองตามจำนวน sensor ที่เลือก พร้อม "Combine with operators" (คลิกเปลี่ยนเครื่องหมายระหว่าง sensor แทนการพิมพ์), สูตรลัดใหม่ (Absolute difference, Spread, Efficiency %), และขั้นตอน "Then apply to the result" สำหรับประมวลผลต่อ
- **Special sensor มีชื่อ/หน่วย/component จริงแล้ว** — เพิ่มช่อง Name/Description/Unit/Component ตอนสร้าง ทำให้ sensor ที่คำนวณขึ้นมาไปอยู่ในกลุ่ม Sensor tab ที่ถูกต้อง แทนที่จะเป็นสตริงสูตรอ่านไม่ออกใน "Uncategorized" — ค่าพวกนี้ persist ข้าม save/reload workspace แล้ว
- **ยุบหน้าต่าง "Failure Group Creation" แยกต่างหากเข้า Dashboard** — จัดการ failure group (สร้าง/เปลี่ยนชื่อ/ลบกลุ่ม, มอบหมาย sensor, แก้ concept/model type/notes) ทำได้ในแท็บ "Failure Groups" ของ Sensor panel บน Dashboard เลย ไม่ต้องเปิดหน้าต่างแยก และกดปุ่ม "Build Model" เปิดหน้าต่าง Predictive Model ได้ตรงจาก Dashboard ทันที (ไม่ต้องผ่านหน้าจอ Failure Group ก่อนเหมือนเดิม)
- **เพิ่มเส้น Alarm setpoint บนกราฟ** — ดึงค่า ALARM_L/LL/H/HH จาก mapping CSV มาแสดงเป็นเส้นอ้างอิงบนกราฟ เปิด/ปิดได้ต่อ sensor จากแท็บ Sensor
- **แสดง error ที่เกิดขึ้นให้เห็นแทนที่จะเงียบหาย** — มีหน้าจอ crash (ErrorBoundary), toast แจ้ง error ที่ปิดได้, ดักจับ error ที่ไม่มีใครจับ (window.onerror/unhandledrejection) และบันทึกลง log file ถาวรที่เครื่อง

### ⚡ Performance / เสถียรภาพ

- **โครงสร้างข้อมูลในหน่วยความจำเปลี่ยนเป็น column-major** (`ColumnarData`) — RAM สูงสุดลดลง ~52%, เวลาโหลดลดลง ~32% (ทดสอบกับไฟล์ 367 MB / 2 ล้านแถว)
- **Frontend ไม่รับข้อมูลดิบทั้งชุดอีกต่อไป** — คำสั่งใหม่ `get_chart_data`/`get_table_page`/`get_scatter_sample`/`export_chart_csv` ประมวลผล filter + aggregate + ลดจำนวนจุดฝั่ง Rust ก่อนส่งมา ทำให้กราฟ/ตารางไม่โหลดข้อมูลเป็นล้านแถวเข้า WebView โดยตรง
- **กราฟเส้นลื่นขึ้นเมื่อข้อมูลเยอะ**: โปรไฟล์ perf พิเศษเมื่อมีจุด >2000 (ปิด animation/smoothing, ใช้ LTTB decimation) และปรับ tooltip/resize ให้ไม่กระตุก
- **Pair plot ไม่โยน draw call ทิ้งเวลาซ้อนกัน** — เรียง draw call ให้รวมกันแทนที่จะ error "Ignoring draw call…"
